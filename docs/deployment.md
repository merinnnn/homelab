# Deploy from each Proxmox repository checkout

The repository is installed at `/root/homelab` on each Proxmox node. Run host orchestration there. Guest payloads are copied from that checkout, not generated by a desktop bootstrap script.

Scripts contain no personal public/private key material and assume no identity filename or desktop path. SSH uses the host's normal client configuration. VM creation accepts an explicitly supplied public-key file; manage authorized keys outside the repository.

## apps01 on pve02

```bash
cd /root/homelab
bash scripts/deploy/proxmox-apps.sh install 100
# Prepare a root-owned mode-600 account JSON file outside Git.
# Its fields are username, password and optional dnsHost.
bash scripts/deploy/proxmox-apps.sh init 100 192.168.1.58 /etc/homelab/uptime-kuma.json
bash scripts/deploy/proxmox-apps.sh publish 100
```

The host uses the guest agent to transfer and run repository payloads, checking guest exit codes. Docker is installed inside the Debian VM. Kuma first binds localhost, then its account/monitors are initialized using a private stdin stream, then it is exposed on the guest's IPv4 interfaces. No private-key path is passed to SSH. The image digest and named data volume persist across repeats. See [apps01 details](apps01.md).

## dns01 on pve01

```bash
cd /root/homelab
# Place one strong password line in a root-owned mode-600 file outside Git.
bash scripts/deploy/proxmox-pihole.sh 100 /etc/homelab/pihole-password
```

The host downloads the official installer from a fixed source commit, verifies its SHA-256, transfers it and the repository guest payload using `pct`, and supplies the password through stdin. Pi-hole web access stays disabled until versions/password are verified. Existing configurations are verified or refused; they are not silently overwritten. Router DNS is not changed.

## Checkout updates and evidence

Use normal Git fetch/fast-forward from the development repository or a verified Git bundle. Preserve server work with an independent backup and Git stash before updating a dirty checkout. Never discard work with reset/clean or overwrite `.git`. Record exact commit IDs and retain unapplied work for review.

Run `node scripts/tests/offline-behavior.cjs`, `node scripts/tests/apps-deployment.cjs`, `node scripts/tests/no-embedded-identities.cjs` and `bash scripts/tests/pihole-native-offline.sh` when Node/Bash are available. A source test pass is separate from actual running service, auth, DNS and persistence checks. Deployment status is recorded in the project reports; these commands alone do not assert that deployment completed.
